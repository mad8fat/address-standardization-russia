# Дизайн-заметки: «Стандартизация адресов»

Публичная редакция проектного документа, по которому собрана первая версия. Дата: 2026-10-21.

## 1. Замысел

Инструмент вырос из личной рабочей задачи автора: регулярно приводить к единому виду списки адресов из разных источников и форматов. Первая версия была внутренним однофайловым HTML-инструментом поверх Яндекс Геокодера. Публичная версия исправляет его главный дефект (адрес без населённого пункта получал город наугад и статус «точный») и становится самостоятельным открытым продуктом.

Позиционирование: не «ещё один геокодер», а готовый инструмент для нетехнического пользователя. Один файл, без установки, без сервера, с ручной проверкой сомнительных адресов.

## 2. Цели, не-цели, анти-цели

Цели:
- Публичный репозиторий с чистой историей, без единого секрета в любом коммите.
- Честные статусы результата: пользователь видит, когда город подставлен геокодером, а не взят из его данных.
- README, по которому человек без подготовки получает ключ, готовит файл и получает результат, а разработчик понимает устройство.
- Живая демонстрация на GitHub Pages.

Не-цели первой версии:
- Другие геокодеры (DaData, 2ГИС, OSM). Архитектура не должна мешать добавить их позже.
- Серверная часть, аккаунты, хранение данных вне браузера.
- Мобильная вёрстка.
- Режим с разбором адресов языковой моделью.
- Проверка по ФИАС/ГАР, индексы, квартиры.

Анти-цели (провал, даже если всё работает):
- В репозиторий попал ключ API, в любой версии истории.
- Инструмент отдаёт «Подтверждён» для адреса без города.
- Опубликованная демка работает на ключе автора.

## 3. Ограничения

- Один `index.html`, без сборки и фреймворков. Единственная библиотека (SheetJS) лежит локально в `vendor/`; шрифты системные; CSP запрещает запросы куда-либо, кроме Яндекса.
- Единственный внешний API: HTTP Геокодер Яндекса. Один запрос на адрес.
- Ключ вводит пользователь; хранится только в `localStorage`.
- Лицензия MIT. Интерфейс и README на русском, короткая английская аннотация в начале README.

## 4. Решения

### 4.1. Модель статусов

| Статус | Когда |
|---|---|
| Подтверждён | Найден дом, и населённый пункт назван в исходной строке (либо назван район или регион, и дом в них единственный) |
| Город не указан | Привязки нет, а среди кандидатов 2 и более разных населённых пунктов; либо назван только район или регион, а домов в них несколько |
| Город не подтверждён | Привязки нет и кандидат один; либо город назван, но одноимённых городов несколько в разных регионах, а регион не назван |
| Дом не найден | Первый результат не дом, или результатов нет |
| Ошибка | Сетевая ошибка или ошибка API после всех попыток |

Дополнительно «Точность» из поля `precision` Яндекса и «Проверка» со значениями «авто» / «вручную». Для статуса «Город не указан» в запись не попадают ни населённый пункт, ни координаты: город выбирает человек.

### 4.2. Алгоритм проверки

Запрос: `results=10`, `lang=ru_RU`, `bbox` по границам России, `rspn=1`, таймаут 20 с, до 3 попыток.

1. Очистка строки: сегменты с маркерами помещения («пом», «кв», «офис», «этаж», «литера», «лит», «вход», «подъезд», «а/я», «павильон») и идущие за ними чисто номерные сегменты выбрасываются; остальные сегменты (в том числе город после маркера) остаются. Маркеры дома не трогаются. Очищенная строка идёт только в запрос. Длина строки ограничена 500 символами.
2. Разбор до 10 кандидатов: вид, точность, регион(ы), район, населённый пункт, улица, дом, координаты. Дом: `kind=house` или `kind=other` с номером дома.
3. Привязка первого кандидата: нормализация слов (нижний регистр, «ё» → «е», без слов-типов, длина ≥ 3); все значимые слова названия населённого пункта (иначе района, иначе региона) должны найтись среди слов исходной строки точно. Слова названия найденной улицы исключаются из сравнения на всех уровнях.
4. Счётчик кандидатов: число различных пар «регион + населённый пункт» среди кандидатов-домов.
5. Статус по таблице 4.1 с двумя уточнениями: привязка по району или региону подтверждает адрес только при одном населённом пункте среди кандидатов; привязка по населённому пункту не подтверждает, если одноимённые пункты есть в других регионах, а регион в строке не назван.

Проверено на реальном API: 26 полных адресов публичных зданий в разных форматах и 18 адресов без города; все 26 подтверждаются, все 18 помечаются. Эталонные наборы: `tests/fixtures/`. Негативные случаи («ул. Пушкина» ≠ Пушкин, «Московская обл., ул. Ленина» ≠ подтверждение, Киров Кировской против Кирова Калужской) закреплены тестами.

Почему не хватает «региона по умолчанию»: внутри одной области «улица Ленина, 12» всё равно находится в десяти населённых пунктах. Ограничение области поиска полезно только для отсечения дальних зарубежных кандидатов.

### 4.3. Режимы и ручная проверка

Автоматический; только сомнительные (остановка на статусе ≠ «Подтверждён»); ручной. В карточке проверки кандидаты показываются равноправно, клик заполняет поля. «Сохранить и дальше» требует населённый пункт и корректные координаты и даёт статус «Подтверждён», проверку «вручную», кандидаты очищаются. «Пропустить» ничего не меняет. Из карточки можно остановить обработку. Повторный проход «только сомнительные» не трогает проверенные вручную адреса; адреса со статусом «Ошибка» можно запросить заново.

### 4.4. Интерфейс

Одна страница: слева панель настроек (ключ, режим, загрузка), справа рабочая область с состояниями: пустое, данные загружены, обработка, ручная проверка, лимит исчерпан (или серия сетевых ошибок), завершение, таблица результатов с фильтром по статусу. Светлая тема, тёмная по `prefers-color-scheme`. Во время обработки загрузка новых данных заблокирована; после остановки или лимита можно продолжить с места остановки.

### 4.5. Выгрузка

Один лист Excel: №, Исходный адрес, Метка, Федеральный округ, Регион, Населённый пункт, Улица и дом, Итоговый адрес, Координаты, Яндекс Карты, 2ГИС, Статус, Точность, Проверка, Кандидаты.

### 4.6. Чистота и безопасность репозитория

Перед каждым коммитом `scripts/check-clean.mjs --staged` ищет в индексе ключи по шаблону UUID и служебные слова из прежней внутренней версии (с учётом UTF-16 и cp1251), проверяет сообщение коммита и сверяет SHA-256 библиотеки в `vendor/`. При совпадении коммит запрещён (`git config core.hooksPath scripts/hooks`). Файл с ключом для живых проверок хранится вне репозитория.

## 5. Оставлено исполнителю

Внутренняя структура кода, точные регулярные выражения (при условии прохождения эталонных наборов), CSS, тексты подсказок, формат CHANGELOG.
