# Алгоритм нормализации и проверки адресов

Версия алгоритма: 1.1.0 (совпадает с `AddrCore.VERSION` и версией npm-пакета).

Документ описывает алгоритм без привязки к языку программирования: его достаточно, чтобы переписать ядро на Python, Go, 1С или другом языке и проверить себя на тестовых векторах из `tests/vectors/`. Эталонная реализация лежит в `addr-core.js`, но читать её не нужно: документ задуман самодостаточным. Эталоном поведения служат векторы в `tests/vectors/`; если реализация, написанная строго по этому тексту, расходится с вектором, это ошибка документации, о ней стоит сообщить в репозиторий.

Условные обозначения:

- `T(s)` — результат токенизации строки `s` (раздел 4): список значимых слов.
- «Слова названия» — `T(название)`.
- `A ⊆ B` для списков слов — каждое слово из `A` есть в `B`.
- Регулярные выражения записаны в привычном синтаксисе Perl/PCRE: `(?=…)` — просмотр вперёд, `(?<!…)` — отрицательный просмотр назад, флаг «без учёта регистра» указан отдельно. Класс `\d` — только ASCII-цифры `0–9`, класс `\s` — любой пробельный символ Unicode, включая неразрывный пробел.

## 1. Задача и принцип

На вход приходит строка адреса в произвольной записи («150000, Ярославская обл, Ярославль г, Кирова ул, дом № 10/25, пом. №№1-5»). На выходе нужны регион, населённый пункт, улица, дом, координаты и **честный статус**.

Геокодер это сопоставитель, а не проверяльщик. На строку «улица Ленина, 12» без города он вернёт дом 12 на улице Ленина в каком-нибудь городе с точностью `exact`, потому что такой дом существует. Поле `precision` описывает, насколько найденный объект совпал с запросом, а не насколько полным был запрос.

Поэтому алгоритм проверяет то, чего геокодер не проверяет:

1. **Привязку**: назван ли населённый пункт (или район, или регион) первого кандидата в исходной строке.
2. **Неоднозначность**: в скольких разных населённых пунктах нашёлся такой дом среди десяти кандидатов.

Из этих двух фактов выводится один из статусов (раздел 9). Главное правило всех решений: при сомнении выбирается сомнительный статус. Ложный «Подтверждён» хуже лишней ручной проверки.

Цепочка обработки одного адреса:

```
исходная строка
  → очистка для запроса (раздел 5; внутри — раскрытие сокращений, раздел 6)
  → запрос к геокодеру, адаптер ответа → список кандидатов (разделы 2–3)
  → классификация: исходная строка + кандидаты → статус, привязка, число городов, верхний кандидат (разделы 7–9)
  → сборка записи для выгрузки (раздел 10)
```

Важно: классификация сравнивает кандидатов с **исходной** строкой (не очищенной). Очистка нужна только для запроса.

## 2. Формат кандидата

Кандидат (`Candidate`) — нейтральное представление одного результата геокодера. Всё, что после адаптера (раздел 3), работает только с этим форматом.

| Поле | Тип | Смысл |
|---|---|---|
| `kind` | строка | Вид объекта: `house`, `street`, `locality`, `province`, `area`, `other`, `hydro` и т. п. Пустая строка, если неизвестен |
| `precision` | строка | Точность совпадения: `exact`, `number`, `near`, `range`, `street`, `other`. Пустая строка, если неизвестна |
| `text` | строка | Полный адрес одной строкой, как его записал геокодер. Алгоритм его не читает |
| `province` | список строк | Все уровни «регион» по порядку, от общего к частному (например, «Уральский федеральный округ», «Тюменская область», «Ханты-Мансийский автономный округ — Югра»). Может быть пустым |
| `area` | строка | Район или городской округ |
| `locality` | строка | Населённый пункт |
| `street` | строка | Улица |
| `house` | строка | Номер дома (с корпусом, строением) |
| `lat`, `lon` | число | Широта и долгота; «не число», если координат нет |

Отсутствующее строковое поле — пустая строка, не «null».

Два правила, которые задаёт адаптер и на которые опирается остальной алгоритм:

- **Последний населённый пункт самый конкретный.** Если в ответе несколько компонентов вида «населённый пункт» (например, «Москва» и затем «Зеленоград»), в `locality` попадает последний.
- **Что считается домом.** Кандидат — дом, если `kind = house`, либо `kind = other` и поле `house` не пустое (так Яндекс отдаёт дома с корпусом). Кандидат `other` без номера дома — не дом. Отсутствующий кандидат — не дом.

## 3. Адаптер Яндекс Геокодера

Это **единственное место, зависящее от Яндекса**. Для другого геокодера пишется другой адаптер, который выдаёт тот же список кандидатов; разделы 4–10 не меняются.

### 3.1. Запрос

Один GET-запрос на адрес:

```
https://geocode-maps.yandex.ru/1.x/?apikey=<ключ>&geocode=<адрес>&format=json&results=10&lang=ru_RU&bbox=19.6,41.1~180,82&rspn=1
```

| Параметр | Значение | Зачем |
|---|---|---|
| `apikey` | ключ пользователя, URL-кодирован | |
| `geocode` | очищенная строка (раздел 5), URL-кодирована как компонент URL (пробел → `%20`, кириллица → UTF-8 в `%XX`) | |
| `format` | `json` | |
| `results` | `10` | десять кандидатов вместо одного: без них нельзя посчитать неоднозначность |
| `lang` | `ru_RU` | названия по-русски, как в исходных строках |
| `bbox` | `19.6,41.1~180,82` (не кодируется) | прямоугольник вокруг России: долгота,широта левого нижнего угла `~` долгота,широта правого верхнего |
| `rspn` | `1` | искать только внутри `bbox`, чтобы «улица Мира, 15» не нашлась в Париже |

Обработка HTTP-ответа:

| Код | Решение |
|---|---|
| 200 | разобрать ответ |
| 403, 429 | остановить всю обработку: ключ отклонён или квота исчерпана |
| прочие 400–499 | ошибка этого адреса, повторять бессмысленно |
| все прочие коды (не 200 и не 4xx) и сетевые ошибки | повторить |

Демо-страница ставит таймаут 20 секунд и делает до трёх попыток; после неудачи адрес получает статус «Ошибка». Текст ошибки берётся из тела ответа: поле `message`, если в объекте есть ещё `statusCode` или `error`; иначе `error.message`, если `error` — объект; иначе `error`, если это строка; иначе пусто.

### 3.2. Разбор ответа

Путь к результатам: `response.GeoObjectCollection.featureMember` — список; каждый элемент даёт одного кандидата в том же порядке. Отсутствие любого звена пути означает пустой список.

Для каждого `featureMember[i].GeoObject`:

| Откуда в ответе | Куда в кандидате |
|---|---|
| `metaDataProperty.GeocoderMetaData.kind` | `kind` |
| `metaDataProperty.GeocoderMetaData.precision` | `precision` |
| `metaDataProperty.GeocoderMetaData.text` | `text` |
| `metaDataProperty.GeocoderMetaData.Address.Components[]` | по правилам ниже |
| `Point.pos` — строка «долгота широта» через пробел | `lon` = первое число, `lat` = второе; нечисловое или отсутствующее значение → «не число» |

Компоненты (`{kind, name}`) обходятся по порядку:

| `kind` компонента | Действие |
|---|---|
| `province` | дописать `name` в конец списка `province` |
| `area` | записать в `area`, только если `area` ещё пустое (берётся первый) |
| `locality` | записать в `locality` (перезаписывается: остаётся последний) |
| `street` | записать в `street` (остаётся последний) |
| `house` | записать в `house` (остаётся последний) |
| прочие (`country`, `district`, `route`, `other`…) | игнорировать |

## 4. Токенизация

`T(s)` превращает строку в список значимых слов:

1. Привести к нижнему регистру (по правилам Unicode).
2. Заменить каждую «ё» на «е».
3. Разбить на части по любой последовательности символов, которые **не** являются строчной кириллической буквой `а`–`я`, латинской буквой `a`–`z` или цифрой `0`–`9`. Дефис, точка, запятая, пробел, «№», «/» — разделители. Прочие буквы (латиница с диакритикой, украинские «і», «ї») тоже разделители.
4. Отбросить части короче трёх символов.
5. Отбросить стоп-слова (таблица ниже).

Порядок слов сохраняется, повторы не удаляются.

Стоп-слова (типы адресных объектов, не участвующие в сравнении названий), дословно из кода, 76 слов:

| | | | | | |
|---|---|---|---|---|---|
| г | город | обл | область | район | с |
| село | п | пос | поселок | рп | д |
| деревня | ул | улица | проспект | пер | переулок |
| ш | шоссе | мкр | микрорайон | дом | кв |
| к | корп | корпус | стр | строение | зд |
| здание | пом | помещ | помещение | офис | литера |
| этаж | федеральный | округ | го | муниципальный | городской |
| городского | республика | край | автономный | рабочий | типа |
| наб | набережная | бульвар | пл | площадь | проезд |
| тупик | аллея | вн | тер | территория | снт |
| днт | влд | владение | им | имени | поселение |
| станица | хутор | аул | квартал | линия | муниципальное |
| образование | городское | станция | федеральная | | |

Слова короче трёх символов в списке ни на что не влияют (их и так отбрасывает шаг 4), но приведены для полноты.

Примеры из `tests/vectors/tokenize.json`:

| Вход | `T` |
|---|---|
| г. Ярославль, Советская ул, дом № 57 | ярославль, советская |
| Усть-Ордынский п, Ленина ул | усть, ордынский, ленина |
| Кремлёвская улица, Орёл | кремлевская, орел |
| муниципальное образование Екатеринбург | екатеринбург |

## 5. Очистка строки перед запросом

Цель: убрать из строки помещения (квартиры, офисы, этажи), на которых Яндекс сдаётся и возвращает только город, но сохранить всё, что описывает здание, и город, стоящий в конце строки.

### 5.1. Маркеры

**Маркер помещения.** Регулярное выражение без учёта регистра, дословно:

```
(^|[\s,;(])(пом|помещ|помещение|кв|офис|оф|этаж|литера|лит|вход|подъезд|а\/я|павильон)(?=\.|\s|$|№|\d)
```

То есть одно из слов таблицы, перед которым начало строки, пробел, `,`, `;` или `(`, а сразу после — точка, пробел, конец строки, «№» или цифра. Слово целиком: «Офицерская», «Подъездная», «Литейный», «кв-л» маркерами не являются.

| Маркеры помещения |
|---|
| пом, помещ, помещение, кв, офис, оф, этаж, литера, лит, вход, подъезд, а/я, павильон |

**Маркер дома.** Регулярное выражение без учёта регистра, дословно:

```
(^|[\s,;])(д|дом|влд|стр|корп)(?=\.|\s|№|\d)
```

То есть одно из слов таблицы, перед которым начало строки, пробел, `,` или `;`, а сразу после — точка, пробел, «№» или цифра (конец строки здесь **не** допускается).

| Маркеры дома |
|---|
| д, дом, влд, стр, корп |

**Номерной сегмент.** Регулярное выражение без учёта регистра, дословно:

```
^[\d\s№\-–—/.,а-яa-z]{0,8}$
```

То есть весь сегмент длиной не больше 8 символов состоит только из цифр, пробелов, «№», дефиса, короткого и длинного тире, «/», точки, запятой, кириллических букв `а`–`я` (без «ё») и латинских `a`–`z`. Такие сегменты («33», «28-31», «12а», «5») — продолжение списка помещений. Сегмент считается номерным, только если в нём есть хотя бы одна цифра.

### 5.2. Процедура

```
вход: raw
raw ← первые 500 символов raw
raw ← раскрыть_сокращения(raw)                      (раздел 6)
сегменты ← raw разбить по ",", каждый обрезать от пробелов, пустые выбросить
оставленные ← []
выбрасывать_номера ← ложь
для i, сег по сегментам:
    м ← первое совпадение маркера помещения в сег
    если м есть:
        если слово маркера (без учёта регистра) = "кв":
            справа ← (часть сег после совпадения) + "," + (сегменты i+1… через ",")
            если в справа есть маркер дома:          ← «кв» это квартал
                оставленные += сег                   (сегмент целиком)
                выбрасывать_номера ← ложь
                следующий сегмент
        голова ← сег от начала до начала слова маркера (разделитель перед словом входит в голову)
        с конца головы срезать символы из набора: любой пробельный символ, ",", ";", "(", "-", "–", "—"
        если голова не пустая: оставленные += голова
        выбрасывать_номера ← истина
        следующий сегмент
    если выбрасывать_номера и сег номерной и в сег есть цифра:
        следующий сегмент                            (выбрасывать_номера остаётся истиной)
    выбрасывать_номера ← ложь
    оставленные += сег
результат ← оставленные через ", "; каждую серию пробельных символов заменить одним пробелом; обрезать края
```

Сегменты со словами после маркера сохраняются: «ул. Ленина, д. 5, кв. 3, г. Ижевск» → «ул. Ленина, д. 5, г. Ижевск».

### 5.3. «кв.» как квартал

«кв» неоднозначно: квартира или квартал. Правило: если **где-либо правее** «кв» (в остатке того же сегмента или в любом следующем сегменте) есть маркер дома, это квартал, и сегмент сохраняется целиком. Иначе это квартира, и действует обычная обрезка. Голый номер без маркера («Ангарск, кв. 84, 5») оставляет «кв» квартирой: запись неоднозначна, и потерять «5» безопаснее, чем отправить в геокодер квартиру как дом. Запись «кв-л» маркером помещения не является вообще и проходит без изменений.

Примеры из `tests/vectors/clean.json`:

| Вход | Результат | Почему |

| ул. Строителей, 25, литера А, этаж 2 | ул. Строителей, 25 | два сегмента с маркерами, голова каждого пустая |
| ул. Ленина 12 кв 5 | ул. Ленина 12 | маркер внутри сегмента: остаётся голова |
| ул. Ленина, д. 5, кв. 3, г. Ижевск | ул. Ленина, д. 5, г. Ижевск | сегмент со словами после маркера сохраняется |
| ,664003,Иркутская обл,,Иркутск г,,Ленина ул,1,,, | 664003, Иркутская обл, Иркутск г, Ленина ул, 1 | пустые поля CSV выброшены |
| Павильон, ул Садовая, д 2 | ул Садовая, д 2 | «Павильон» — маркер, голова пустая; «ул Садовая» не номерной |

| СПб, Невский пр., 28, оф. 5 | Санкт-Петербург, Невский пр., 28 | сокращение раскрыто, офис убран |
| Ангарск, кв. 84, дом 5 | Ангарск, кв. 84, дом 5 | маркер дома правее «кв» — квартал |
| Ангарск кв. 84 д. 5 | Ангарск кв. 84 д. 5 | то же внутри одного сегмента |

| Ангарск, кв. 84, 5 | Ангарск | правее только голый номер — квартира, «5» номерной |

## 6. Раскрытие сокращений городов

Сокращения названий городов заменяются полным названием, которое возвращает геокодер. Раскрытие применяется к исходной строке:

- в очистке перед запросом (раздел 5, после обрезки до 500 символов);
- в начале классификации (раздел 7), до любой токенизации.

Перед раскрытием все типографские тире и дефисы (U+2010 `‐`, U+2011 `‑`, U+2012 `‒`, U+2013 `–`, U+2014 `—`, U+2015 `―` и минус U+2212 `−`) заменяются обычным дефисом `-`: «Ростов–на–Дону» с коротким тире обрабатывается так же, как «Ростов-на-Дону».

Словарь, дословно из кода. Каждый шаблон применяется без учёта регистра, ко всем вхождениям, в порядке таблицы. Вхождение засчитывается только **по границам слова**: символ перед ним и символ после него не должны быть буквой `а`–`я`, `ё`, `a`–`z` (без учёта регистра). Цифры, пробелы и знаки препинания границами являются. Так «Мск» не находится внутри «Омска», а «Ростов» в «Ростовская обл» не раскрывается.

| Шаблон (регулярное выражение) | Ловит, например | Раскрытие |
|---|---|---|
| `спб\|с\.?\s*-?\s*петербург\|санкт\s+петербург` | СПб, С.-Петербург, С-Петербург, С Петербург, Санкт Петербург | Санкт-Петербург |
| `н\.?\s*новгород` | Н. Новгород, Н.Новгород | Нижний Новгород |
| `ростов[\s-]*(?:на\|н)[\s./-]*д(?:ону)?` | Ростов н/Д, Ростов-на-Д, Ростов на Дону, Ростов-на-Дону | Ростов-на-Дону |
| `екб\|е-бург` | Екб, Е-бург | Екатеринбург |
| `мск` | Мск | Москва |
| `нск\|н-ск` | Нск, Н-ск | Новосибирск |

(В таблице `\|` — это экранированная для разметки вертикальная черта, то есть альтернатива `|`.)

Полная граница вхождения: перед шаблоном отрицательный просмотр назад `(?<![а-яёa-z])`, после — отрицательный просмотр вперёд `(?![а-яёa-z])`.

«Влг» намеренно не раскрывается: Волгоград и Вологда неразличимы, адрес должен остаться сомнительным.

Раскрытие идемпотентно: повторное применение к уже раскрытой строке ничего не меняет (полные формы либо не совпадают с шаблонами, либо заменяются сами на себя). Реализации достаточно применить его один раз.

Пример из `tests/vectors/confirmed.json`: «СПб, Невский пр., 28» раскрывается в «Санкт-Петербург, Невский пр., 28», кандидат «Санкт-Петербург» подтверждается на уровне `locality`.

## 7. Привязка

Привязка отвечает на вопрос: на каком уровне — населённый пункт (`locality`), район (`area`) или регион (`province`) — исходная строка подтверждает данного кандидата. Ответ: один из трёх уровней или «нет».

Везде ниже «вход» — исходная строка **после** раскрытия сокращений (раздел 6). Очистка (раздел 5) к нему не применяется.

### 7.1. Пул слов

`Пул(к)` для кандидата `к` = множество слов `T(вход)` минус множество слов `T(к.street)`.

Слова названия улицы кандидата не могут подтверждать ни город, ни район, ни регион: «ул. Пушкина» не подтверждает город Пушкин, «ул. Московская» не подтверждает Московскую область. Слово, совпавшее с улицей, удаляется из пула целиком, даже если во входе оно встречается ещё и отдельно.

### 7.2. Составные имена и отдельные слова входа

Вход делится на «дефисные слова»: максимальные последовательности букв (кириллица с «ё», латиница, без учёта регистра), цифр и дефисов «-». Все прочие символы, включая пробел, точку, запятую и тире «–», «—», — разделители.

Для каждого дефисного слова `w` вычисляется `t = T(w)` (дефис внутри `T` — разделитель):

- если `w` содержит дефис, в `t` не меньше двух слов и **в каждом** слове `t` есть хотя бы одна буква — `t` добавляется в список **составных имён** (как список слов);
- иначе каждое слово `t` добавляется в множество **отдельных слов**.

| Фрагмент входа | Результат |
|---|---|
| Ростов-на-Дону | составное имя [ростов, дону] («на» короче трёх символов) |
| Москва-Сити | составное имя [москва, сити] |
| Ханты-Мансийский автономный округ - Югра | составное имя [ханты, мансийский]; «Югра» отдельное слово; одиночный «-» между пробелами ничего не даёт |
| Римского-Корсакова | составное имя [римского, корсакова] |
| 10-12, 10-А, 28-31 | ничего: после `T` слов меньше двух (короткие отброшены) |
| 100-120 | отдельные слова 100, 120: в них нет букв |
| кв-л | ничего: «кв» — стоп-слово, «л» короткое |
| Комсомольск на Амуре (через пробелы) | отдельные слова комсомольск, амуре: дефиса нет, составного имени нет |

### 7.3. Допустимость названия

Название с непустым списком слов `N = T(название)` **допустимо** для входа, если для каждого слова `s` из `N` выполнено хотя бы одно:

- `s` есть среди отдельных слов входа;
- `s` входит в какое-то составное имя `C` входа, и `C ⊆ N` (название покрывает это составное имя целиком).

Это правило «по вхождениям»: слову достаточно одного допустимого вхождения. Часть составного имени не подтверждает целое: кандидат «Ростов» не допустим для входа «Ростов-на-Дону, …» (слово «ростов» стоит только внутри составного имени [ростов, дону], а [ростов] его не покрывает). Но «г. Москва, Москва-Сити, …» допускает «Москва»: слово «москва» стоит ещё и отдельно.

### 7.4. Покрытие составных имён (только для уровней района и региона)

Кандидат `к` **покрывает составные имена входа**, если каждое составное имя `C` входа удовлетворяет хотя бы одному:

- все слова `C` есть в `T(к.street)` (это название улицы, геокодер нашёл ту же улицу);
- существует одно название кандидата `n` из набора {`T(к.locality)`, `T(к.area)`, `T(к.province[0])`, `T(к.province[1])`, …} (пустые не рассматриваются) такое, что `C ⊆ n`.

Смысл: если вход подтверждается только регионом, а в нём есть составное имя, которое не похоже ни на одно название кандидата, это почти наверняка город, которого кандидат не нашёл («Камчатский край, Петропавловск-Камчатский, …» при кандидате «Елизово»). Привязку по региону в таком случае давать нельзя. Составные названия улиц («ул. Римского-Корсакова») на это не влияют, если геокодер нашёл ту же улицу.

### 7.5. Проверка уровня

`Совпадает(уровень, к)`:

```
если уровень ≠ locality и к не покрывает составные имена входа (7.4): ложь
названия ← к.province (весь список), если уровень = province
            [к.locality], если уровень = locality
            [к.area], если уровень = area
истина, если хотя бы для одного названия из названия:
    N = T(название) не пусто
    и N ⊆ Пул(к)                         (все слова, точным совпадением)
    и название допустимо для входа (7.3)
```

Совпадение только точное, по целым словам: «пушкина» не подтверждает «Пушкин», «кирова» не подтверждает «Киров».

`Привязка(к, без_locality)`: проверить уровни по порядку `locality → area → province`, пропустив `locality`, если `без_locality` истинно; вернуть первый совпавший уровень, иначе «нет».

Публичная функция `matchAnchor(вход, кандидат)` — это ровно `Привязка(кандидат, ложь)` после раскрытия сокращений во входе. Функция `compoundNames(вход)` возвращает список составных имён из 7.2.

### 7.6. Предпочтение более длинного названия

Перед привязкой верхнего кандидата `верх` ищется **более длинное совпадение**: первый по порядку кандидат `к` **любого вида** (не только дом), у которого:

- число слов `T(к.locality)` строго больше числа слов `T(верх.locality)`;
- `T(к.locality) ⊆ Пул(верх)` (пул по улице **верхнего** кандидата: название улицы из строки не должно «находить» СНТ или посёлок с тем же словом в названии);
- `к.locality` допустимо для входа (7.3).

Число слов считается по списку `T` с повторами. Если у `верх` населённого пункта нет, его длина 0.

Берётся **первый** подходящий кандидат в порядке списка, и только он. Если первым подходит кандидат, который нельзя продвинуть (см. ниже), а ниже есть подходящий кандидат-дом, решение принимается по первому: уровень `locality` запрещается, перестановки нет, дом ниже не рассматривается.

**Улица названа во входе**: `T(к.street)` не пусто и каждое его слово есть в `T(вход)` (полный набор слов входа, без вычитания улицы верхнего кандидата).

Дальше:

- найден кандидат-дом и его улица названа во входе → он становится верхним (переносится в начало списка, остальные сохраняют порядок), результат помечается `reordered = истина`;
- найден кандидат не дом или дом, чья улица во входе не названа → привязка верхнего кандидата на уровне `locality` запрещена (`без_locality = истина`); верхний не меняется, `reordered = ложь`;
- не найден → ничего не меняется.

Улица обязательна потому, что кандидат ниже по списку — не выбор геокодера: совпадения одного названия города мало, нужно отдельное подтверждение.

Пример из `tests/vectors/compound.json`: вход «Ростов-на-Дону, Будённовский пр., 1», кандидаты «Ростов» (Ярославская область, дом) и «Ростов-на-Дону» (Ростовская область, дом). «Ростов-на-Дону» длиннее (2 слова против 1), допустим, и это дом: он становится верхним, `reordered = истина`, привязка `locality`, «Подтверждён». Вход «Ростов на Дону, Будённовский пр., 1» (сокращение из раздела 6 превращает «Ростов на Дону» в «Ростов-на-Дону») с теми же кандидатами, но «Ростов-на-Дону» — кандидат вида `locality`, а не дом: верхний «Ростов» привязывать по `locality` нельзя, по району и региону он не подтверждается → «Город не подтверждён», `reordered = ложь`.

Пример из `tests/vectors/rules.json`: вход «ул. Красная Поляна, 5», кандидаты «Москва, Краснополянская улица, 5» (дом) и «Красная Поляна, улица Защитников Кавказа, 5» (Краснодарский край, дом). «Красная Поляна» длиннее «Москвы» (2 слова против 1) и целиком названа во входе — но это название улицы, а не города. Улица второго кандидата [защитников, кавказа] во входе не названа, поэтому перестановки нет: верхней остаётся «Москва», уровень `locality` запрещён, по региону «Москва» не подтверждается (слова «москва» во входе нет), привязки нет, два города → «Город не указан», `reordered = ложь`.

Поле `reordered` — часть результата классификации; в запись и выгрузку оно не попадает.

## 8. Подсчёт населённых пунктов

### 8.1. Число разных населённых пунктов

`Число_городов(кандидаты)` = число разных ключей среди кандидатов-**домов** (раздел 2), где ключ = элементы `province` через «/» + «|» + `locality`. Строки сравниваются как есть, без токенизации. Кандидаты не дома не считаются. Дом с пустым `locality` тоже даёт ключ (элементы `province` + «|» + пустая строка) и считается отдельным населённым пунктом.

Пример: «улица Ленина, 12» из `tests/vectors/no-city.json` — десять домов в десяти городах (Киров, Ижевск, Благовещенск…), число 10. «Пермь, ул. Ленина, 23, офис 101» из `confirmed.json` — три дома: два в Перми и один в посёлке Звёздный, число 2.

Число считается по исходному списку кандидатов; перестановка из 7.6 его не меняет.

### 8.2. Одноимённые населённые пункты в разных регионах

`Одноимённые(верх, кандидаты)`:

```
имя ← слова T(верх.locality) через пробел
если имя пустое: ложь
регионы ← множество строк (элементы province через "/")
          по всем кандидатам-домам, у которых слова T(locality) через пробел = имя
истина, если в регионах не меньше двух элементов
```

Пример: кандидаты «Киров, Кировская область» и «Киров, Калужская область», оба дома. Вход «г. Киров, ул. Ленина, 12» → одноимённые есть, регион не назван → «Город не подтверждён» (`tests/vectors/rules.json`). Вход «Кировская обл, г. Киров, ул. Ленина, 12» → регион назван → «Подтверждён» (`tests/core-classify.test.mjs`).

## 9. Классификация и таблица статусов

Результат классификации: `status` (строка статуса), `anchor` (`locality`, `area`, `province` или «нет»), `candidateCount` (число из 8.1), `top` (верхний кандидат после возможной перестановки, или «нет», если кандидатов нет), `reordered` (истина/ложь).

Статусы (строки дословно, они же попадают в выгрузку): «Подтверждён», «Город не указан», «Город не подтверждён», «Дом не найден», «Ошибка». «Ошибка» классификация не выдаёт: её ставит сборка записи при сетевой ошибке (раздел 10).

Процедура:

```
вход ← раскрыть_сокращения(вход)
верх ← первый кандидат или «нет»;  reordered ← ложь
число ← Число_городов(кандидаты)                                  (8.1)
если верх не дом: вернуть «Дом не найден», anchor = нет
определить составные имена и отдельные слова входа                (7.2)
к ← более длинное совпадение для верх                            (7.6)
без_locality ← ложь
если к есть, к дом и улица к названа во входе (7.6):
    кандидаты ← [к] + остальные; верх ← к; reordered ← истина
иначе если к есть:   без_locality ← истина
anchor ← Привязка(верх, без_locality)                            (7.5)
… дальше по таблице
```

Проверки в точном порядке выполнения. Срабатывает первая подходящая строка.

| № | Условие | Статус | Пример из векторов |
|---|---|---|---|
| 1 | Кандидатов нет или первый кандидат не дом | Дом не найден | `no-city.json`: «"бизнес-центр Альфа"» — первый кандидат вида `hydro` |
| 2 | Привязка `locality`, есть одноимённые в разных регионах (8.2) и `Совпадает(province, верх)` ложно | Город не подтверждён | `rules.json`: «г. Киров, ул. Ленина, 12» с двумя Кировами |

Замечания:

- В строке 2 проверка региона — полная `Совпадает(province, верх)` из 7.5, включая покрытие составных имён.
- В строке 5 «Подтверждён» по району или региону честен потому, что дом нашёлся в единственном населённом пункте: геокодер ничего не угадывал.
- Строка 4 и строка 6 дают одинаковый статус, строки 5 и 7 различаются только привязкой.

| `candidatesText` | Кандидаты | пусто |
| `street`, `house`, `lat`, `lon`, `error`, `candidates` | — (служебные) | пусто / «не число» / пустой список |

Порядок колонок выгрузки: №, Исходный адрес, Метка, Федеральный округ, Регион, Населённый пункт, Улица и дом, Итоговый адрес, Координаты, Яндекс Карты, 2ГИС, Статус, Точность, Проверка, Кандидаты. «№» — порядковый номер с единицы; отсутствующие значения выгружаются пустой строкой.

### 10.1. Заполнение по статусу

```
если ошибка запроса:
    status ← «Ошибка»; error ← текст ошибки; больше ничего не заполнять
status ← статус классификации
candidates ← копия списка кандидатов
верх ← top из классификации (после перестановки)
если верх есть и status = «Город не указан»:
    street ← верх.street; house ← верх.house
    streetAndHouse ← street и house через ", " (пустые пропустить)
    locality, province, district, precision, координаты, ссылки, finalAddress — пустые
иначе если верх есть:                                 (любой другой статус, включая «Дом не найден»)
    precision ← подпись точности(верх.precision)
    district ← федеральный округ(верх.province)
    province ← последний элемент верх.province (или пусто)
    locality, street, house ← из верх
    заполнить производные поля (ниже)
если status ∈ {«Город не указан», «Город не подтверждён»}:
    candidatesText ← список городов-кандидатов (ниже)
```

Главное: при статусе «Город не указан» угаданный геокодером город, регион и координаты в запись **не попадают**. Человек выбирает город сам из списка «Кандидаты».

Производные поля:

- `streetAndHouse` = `street`, `house` через «, », пустые пропускаются.
- `finalAddress` = `locality`, `street`, `house` через «, », пустые пропускаются.
- Если `lat` и `lon` — числа: `coordinates` = «`lat`, `lon`» (кратчайшая десятичная запись числа, например «55.7558, 37.6173»); `yandexLink` = `https://yandex.ru/maps/?ll=<lon>%2C<lat>&z=17&pt=<lon>%2C<lat>,pm2rdm`; `dgisLink` = `https://2gis.ru/search/<finalAddress, URL-кодирован как компонент>?m=<lon>%2C<lat>%2F18`. Иначе все три пустые.

Подписи точности (`precision` → колонка «Точность»); любое другое значение даёт пустую строку:

| `precision` | Подпись |
|---|---|
| exact | точный дом |
| number | тот же номер, другой корпус |
| near | ближайший дом |
| range | приблизительно |

Федеральный округ: первый элемент `province`, который есть в таблице; если нет ни одного — пусто.

| Элемент `province` | Округ |
|---|---|
| Центральный федеральный округ | ЦФО |
| Северо-Западный федеральный округ | СЗФО |
| Южный федеральный округ | ЮФО |
| Северо-Кавказский федеральный округ | СКФО |
| Приволжский федеральный округ | ПФО |
| Уральский федеральный округ | УФО |
| Сибирский федеральный округ | СФО |
| Дальневосточный федеральный округ | ДФО |

Список городов-кандидатов: по кандидатам-домам в порядке списка взять `locality`, а если он пустой — последний элемент `province`; пустые имена пропустить, повторы убрать (оставить первое вхождение), соединить через «; ». Для «улица Ленина, 12» это «Киров; Ижевск; Благовещенск; …».

### 10.2. Входные строки

Это часть демо-страницы, но функции лежат в ядре:

- Текстовый ввод: строки по переводу строки (`\n` или `\r\n`), пустые (из одних пробелов) выбрасываются, каждая строка делится по табуляции: первая часть — адрес, вторая — метка; части обрезаются от пробелов.
- Строки таблицы или текста превращаются в записи: адрес — первая ячейка, метка — вторая, обе обрезаются от пробелов и ограничиваются 500 символами. Строки с пустым адресом пропускаются. Первая непустая строка пропускается как заголовок, если её адрес подходит под выражение без учёта регистра `^(исходный\s+)?адрес(а)?(\s+[а-яё]+)?\s*:?$` («Адрес», «Адреса», «адрес:», «Адрес доставки», «Исходный адрес»).

## 11. Тестовые векторы

Векторы лежат в `tests/vectors/`; формат, правила пополнения и псевдокод прогона описаны в [tests/vectors/README.md](../tests/vectors/README.md). Кратко:

- `confirmed.json` — полные адреса публичных зданий, все дают «Подтверждён».
- `no-city.json` — адреса без населённого пункта, ни один не подтверждается.
- `compound.json` — составные имена и предпочтение более длинного названия (раздел 7); кандидаты в этом файле синтетические: они закрепляют правила, а не воспроизводят реальные ответы.
- `rules.json` — синтетические кейсы на строки таблицы статусов и правила раздела 7.6, которых нет в реальных ответах геокодера.
- `tokenize.json` — пары «строка → список слов» (раздел 4).
- `clean.json` — пары «строка → очищенная строка» (разделы 5–6).

В файлах классификации кандидаты уже в нейтральном формате (раздел 2), поэтому реализации не нужен ни ключ, ни сеть. Кроме `status` и `anchor`, в `expected` могут быть поля `topLocality` (ожидаемый `locality` верхнего кандидата после перестановки) и `reordered`.

Реализация совместима, если проходит все кейсы всех файлов.
