# Changelog

## [1.1.0] — 2026-10-24

Ядро стало отдельным модулем, появились описание алгоритма и тестовые векторы, исправлены шесть отложенных проблем.

- Ядро вынесено из `index.html` в отдельный файл `addr-core.js`: обычный скрипт без зависимостей, подключается тегом `<script src>` в браузере (страница по-прежнему открывается с диска) и через `require` или `import` в Node. Версия доступна как `AddrCore.VERSION`.
- npm-пакет `address-standardization-russia`: только ядро, описание алгоритма, README и лицензия.
- Описание алгоритма без привязки к языку (`docs/algorithm.md`) и тестовые векторы в `tests/vectors/`: кандидаты в нейтральном формате, любую реализацию можно проверить без ключа и сети. Граница «геокодер / алгоритм» явная: от Яндекса зависит только адаптер `parseGeocoderResponse`.
- Раскрытие сокращений городов перед запросом и проверкой: «СПб», «Н. Новгород», «Ростов н/Д», «Екб», «Мск», «Нск» и их варианты, только целыми словами. «Влг» намеренно не раскрывается. Типографские тире («Ростов–на–Дону») приводятся к дефису.
- Составные названия через дефис неделимы: ярославский «Ростов» больше не подтверждается строкой «Ростов-на-Дону», «Комсомольск» — строкой «Комсомольск-на-Амуре». При привязке только по региону непокрытое составное название оставляет адрес сомнительным. Если среди кандидатов есть населённый пункт с более длинным названием, целиком названным в строке, предпочитается он: дом с таким названием и улицей, тоже названной в строке, становится первым (`classify` возвращает `reordered: true`), иначе город первого кандидата просто не подтверждается.
- «кв.» считается кварталом, а не квартирой, если правее в строке есть маркер дома («д.», «дом», «влд», «стр.», «корп.»): «Ангарск, кв. 84, д. 5» уходит в геокодер целиком.
- Проверка чистоты распаковывает `.xlsx`, `.xlsm` и `.docx` и ищет ключи в их содержимом.
- Галочка «Запоминать ключ в этом браузере» (без неё ключ живёт только до закрытия вкладки) и кнопка «Забыть ключ».
- GitHub Actions на push и pull request в `main`: тесты, проверка чистоты и gitleaks по коммитам, попавшим в push или pull request, правило на формат ключа Яндекса в `.gitleaks.toml`.

## [1.0.0] — 2026-10-21

Первая публичная версия.

- Пять честных статусов вместо «Точный / Приблизительный»: «Подтверждён», «Город не указан», «Город не подтверждён», «Дом не найден», «Ошибка».
- Проверка привязки найденного населённого пункта к исходной строке и подсчёт городов-кандидатов (запрос десяти результатов вместо одного). Название улицы не может подтверждать одноимённый город или регион; одноимённые города в разных регионах требуют регион в строке.
- Для статуса «Город не указан» угаданный город в запись и выгрузку не попадает.
- Очистка сегментов «пом.», «кв.», «офис», «этаж», «литера» перед запросом к геокодеру с сохранением города, стоящего после них.
- Поиск ограничен территорией России (`bbox` + `rspn=1`), таймаут запроса 20 с, до трёх попыток.
- Ключ API вводит пользователь, хранится в `localStorage`, в коде ключей нет; поле ключа маскируется.
- Режим «останавливаться только на сомнительных», повторный проход по сомнительным, повтор адресов с ошибкой, продолжение после остановки или лимита.
- Карточка ручной проверки со списком кандидатов, проверкой координат и кнопкой «Остановить».
- Колонки «Проверка» (авто / вручную) и «Кандидаты» в выгрузке.
- Пауза после пяти сетевых ошибок подряд вместо «сжигания» списка статусом «Ошибка».
- Защита от загрузки новых данных во время обработки и от двойного запуска цикла.
- SheetJS 0.20.3 локально в `vendor/` (закрыты CVE старых версий на CDN), системные шрифты, Content-Security-Policy, ограничение размера файла и числа строк.
- Тёмная тема по системной настройке.
- Тесты ядра в Node без сборки; проверка индекса на секреты перед коммитом, включая UTF-16 и подмену библиотеки.
